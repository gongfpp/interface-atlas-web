A SMALL PATH, A COMPLETE OUTCOME

Make a form easier to complete

Try input, validation, failure and recovery to see how components form a complete flow.

Preserve entered values, explain corrections beside each field, prevent duplicate submissions and allow retries after failure. The two interactive examples below cover the complete path.

Pick the parts in this order

Each stop explains the problem it solves and the trade-off to consider.

01

Input: start with labels and help ↗

Keep labels visible and use examples as supporting text. Explain what is needed before showing an error.

02

Validation: explain the correction ↗

Associate errors with fields and move focus to the first invalid field. Failed validation must not erase entered values.

03

Upload: make progress understandable ↗

Provide feedback for selection, upload, failure, retry and completion. Choosing a local file does not mean it has been saved on a server.

04

Alert: keep recovery close ↗

Keep actionable errors visible and explain both what happened and what the user can do next.

05

Spacing: reveal relationships ↗

Keep a field’s label, input and help close together, with more space between separate groups.

Implement this interface task：Make a form easier to complete

Preserve entered values, explain corrections beside each field, prevent duplicate submissions and allow retries after failure. The two interactive examples below cover the complete path.

- Input: start with labels and help：Keep labels visible and use examples as supporting text. Explain what is needed before showing an error.
- Validation: explain the correction：Associate errors with fields and move focus to the first invalid field. Failed validation must not erase entered values.
- Upload: make progress understandable：Provide feedback for selection, upload, failure, retry and completion. Choosing a local file does not mean it has been saved on a server.
- Alert: keep recovery close：Keep actionable errors visible and explain both what happened and what the user can do next.
- Spacing: reveal relationships：Keep a field’s label, input and help close together, with more space between separate groups.

Complete workflows:
- File upload: choose → show file name → upload progress → cancellation → failure retaining selection → retry → success → removal. State accepted types and size limits; distinguish local selection from server persistence.
- Edit profile: persistent labels → required and email validation → focus first invalid field → prevent duplicate saves → preserve input on failure → retry → success feedback; offer keep editing or discard when leaving unsaved changes.
- A demo may use a controllable one-time failure. Production must use real endpoints; never report simulated success as persisted data.

Requirements: responsive layout, visible focus and keyboard operation; clear loading, empty, error and success feedback; never rely on color alone. State the stack and necessary assumptions first.
