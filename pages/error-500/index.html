概览交互实验室形式与用法实现要点复制 Prompt

这是什么

在后端异常、请求无法完成时展示的页面：不暴露内部细节，用中性语气说明是服务端问题，给出稍后重试或联系支持的路径，并尽量保留用户已输入的内容。它承担故障期间的信任维护。

结构拆解 · 悬停、聚焦或点选部位

✓ 适用场景

  • 服务端异常、数据库或依赖不可用
  • 请求超时或网关错误
  • 需要在不暴露细节的前提下说明故障

✕ 不适用场景

  • 页面地址不存在（应使用 404 页面）
  • 用户无权限访问（应提示权限或登录）
  • 可自动重试立即恢复的瞬时抖动

页面结构

  1. 01

    状态码与标题

    用 500 与中性标题说明是服务端问题，而非用户操作错误。

  2. 02

    错误说明

    说清正在恢复、是否需要用户操作，不暴露堆栈或内部 ID。

  3. 03

    重试操作

    主按钮重试请求，可带倒计时与尝试次数。

  4. 04

    故障状态

    展开可看影响范围与更新时间，默认收起。

  5. 05

    支持入口

    提供状态页或联系支持，供重试无果时求助。

实现要点

flexgridmin-height: 100vhtext-align: centermax-width: 48ch

与 404 共用一套居中骨架：min-height 100vh 加 flex 居中，内容限制在 48ch。重试按钮点击后禁用并显示进行中状态， 用 aria-live 播报结果变化。服务端返回 5xx 状态码；日志记录请求 ID 供支持排查，但不要把堆栈渲染到页面上。

404 页面404 Page

在用户请求的地址不存在时展示的兜底页面：用一句人话说明发生了什么，提供返回首页、搜索或推荐入口，把一次失败访问转成继续浏览的机会。它不解决问题本身，但决定用户是离开还是留下。
