What is it

A fallback screen for missing addresses. It explains the situation plainly and offers home, search or recommended links for a next step.

404

This page is missing

The address may be mistyped, or the page has moved.

Try the search or a suggested link

Explore the anatomy · focus or select a part

✓ When to use

  • A requested path is missing or retired
  • A user types or follows a broken link
  • Deleted content must still catch old traffic

✕ When not to use

  • Backend failures — use a server error page instead
  • Authentication or permission gaps — route to login instead
  • Old links that can redirect precisely — just forward them

Page structure

  1. 01

    Code and heading

    A 404 with a plain-language heading so users know nothing crashed.

  2. 02

    Message

    One sentence explaining the missing address, free of jargon or blame.

  3. 03

    Illustration

    A light illustration or icon that softens the failure without dominating.

  4. 04

    Actions

    A primary home button and secondary back or support links.

  5. 05

    Recommendations

    A search box or popular links that point to a next step, not a dead end.

Implementation

flexgridmin-height: 100vhtext-align: centermax-width: 48ch

Center the page with min-height 100vh plus flex, and cap the copy at 48ch for readability. Use a large font-serif status code as the visual anchor, with search and links inside the same max-width container. Return a real 404 status code rather than a 200 wrapper so search engines do not index empty pages.

Empty State空状态

When a list or page has no data, don't leave a void — fill it with an illustration, one sentence of explanation and a clear next action. It solves the "blank screen" problem where users can't tell what happened or what to do next, turning dead space into a starting point: onboarding for first use, a way out for fruitless searches.
